### 実行環境
| 項目 | 内容 |
|---|---|
| ホスト環境 | macOS |
| コンテナ実行環境 | Colima上のDocker |
| コンテナ管理 | Docker Compose（docker-compose） |
| ベースイメージ | node:22-bookworm-slim（Debian Bookworm系） |
| Node.js | 22.23.3 |
| Astro | package.json の指定は ^7.3.6 |
| Mac側の作業場所 | ~/projects/docker-practice/portfolio-new |
| コンテナ内の作業場所 | /app |
| ファイル共有 | bind-mount `.:/app` |
| 起動コマンド | `npm run dev -- --host 0.0.0.0` |
| ブラウザの接続先 | http://localhost:4321/ |

### 起きたこと

astroの開発サーバーをDockerで使っているとき、index.astroを変更しても変更が反映されていませんでした。Astroの開発サーバーは内部でViteを利用しています。Viteがファイルの変更を検知すると、変更された内容を開発サーバーに反映します。

### 調査

- コンテナがbind mountでmacのソースファイルであるindex.astroの変更をよみとれているか確認しました。
```shell
docker-compose exec portfolio cat /app/src/pages/index.astro
```
こちらは認識できていました。

- curlでHTTPレスポンスをみると、古いHTMLであることがわかりました。

ここでmac->dockerのファイル共有はできているものの、astro/viteが変更を認識できていないと考え、一定間隔でファイルの変更を監視するようにしました。

astro.config.mjs
```javascript
  import { defineConfig } from "astro/config";

  export default defineConfig({
    vite: {
      server: {
        watch: {
          usePolling: true,
          interval: 500,
        },
      },
    },
  });

```
usePolling: trueではOSからの変更通知を待つ代わりに、一定間隔でファイルの状態を確認します。今回はinterval: 500なので500ms間隔です。その代わり、通常のイベント監視よりCPU負荷が増える可能性があります。
この設定で自動更新ができるようになりました！

### 考察

通常のastroでは
```
保存 -> OSが変更イベントを発生 -> Viteがイベントをうけとる -> Astroが反映
```
ですが、今回は、ファイルの内容自体はコンテナまで共有されていましたが、Viteが利用するファイル変更通知は正常に届いていなかった可能性があります。Mac → Colima VM → Dockerコンテナという構成のため、どの段階で変更通知が失われていたのかまでは今回確認できていません。
### まとめ

bind mountが正常でも、ファイル変更監視も正常とは限りません。今回、Dockerのbind-mountは単にファイルを見せるだけではなく、開発環境では「変更をどう検知するか」も重要だと分かりました。
