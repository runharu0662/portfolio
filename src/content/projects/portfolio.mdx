## portfolioの作成にあたって

理解を放棄しないように作成の過程を記録していこうと思います。

### dockerから

- node.jsの実行環境を用意するために最小限のDockerfileを作成します。

``` Dockerfile
FROM node:22-bookworm-slim

WORKDIR /app

CMD ["node", "--version"]
```
これはmacのディレクトリをコンテナ内部`/app`にコピーして作業ディレクトリとして`node --version`を実行してます。また、コンテナ内部にはlinuxのようなファイル構造があります。

- 次にmac側のソースを使うために`compose.yaml`を作ります
``` yaml
services:
  portfolio:
    build: .
    # working_dirはDockerfilesで設定されているのでなくても問題ありません。
    # 通常compose.yaml側が優先されます。
    working_dir: /app
    # volumesでmacのカレントディレクトリとコンテナを共有しています。
    volumes:
      - .:/app
    #コンテナとmacのポートを共有しています。
    ports:
      - "4321:4321"
    command: npm run dev -- --host 0.0.0.0


```
### Astro

#### ひな形の作成
docker側でnpmの操作をします。
```shell
docker compose run --rm portfolio npm init -y
```
package.jsonを編集します
```json
{
    "name": "portfolio-new",
    "version": "1.0.0",
    // npmへのパッケージ公開を防ぐためにprivateをtrueに
    "private": true,
    // javascriptで import/exportを使うためにtypeをmoduleに
    "type": "module",
    // コマンドに名前をつける場所
    "scripts": {
        "dev": "astro dev",
    }
}
```
docker側でAstroのひな形を作成します。
```shell
docer compose run --rm portfolio npm install astro
```
`app/src/pages/index.astro`,`app/src/styles/global.css`を作成し、起動中のコンテナが認識しているか`exec`で確認します。まずdocker-composeでコンテナを起動します。
```shell
docker compose up
```
```shell
docker-compose exec portfolio ls -la src/pages
```
astroが自動で編集を検知してくれなかったので、`astro.config.mjs`に以下を追記しました。
```javascript
  import { defineConfig } from "astro/config";

  export default defineConfig({
    vite: {
      server: {
        watch: {
          usePolling: true,
          interval: 500,
        },
      },
    },
  });
```
この問題についてまとめました。
[Docker上のAstroで、保存した変更が反映されなかった問題](/learning/docker/astro-file-watch-polling/)

今回、Markdownで書いた記事をサイトに表示するために、Astroというフレームワークを使いました。

  astro:content が提供する getCollection() で記事データを取得し、タイトルや説明を一覧に表示し
  ます。記事の詳細ページでは、render() でMarkdown本文を表示するためのコンポーネントを取得しま
  す。

  ページや部品は .astro ファイルに書きます。先頭の --- 内でJavaScriptを使い、HTML内の `{}` で値
  や式を表示できます。また、HeaderやFooterをコンポーネントとして分け、複数のページで共通の構造
  を使えることも学びました。

### tips

- 処理する場所：.astro の先頭の --- 内は、開発サーバーやビルド時に実行されます。ブラウザで動
    かす処理は `<script>` に書きます。

  - URLを作る仕組み：src/pages/ の配置がURLに対応します。記事をコレクションへ追加するだけでは
    URLはできず、今回の [id].astro と getStaticPaths() が記事ごとのページを作ります。

  - 公開時の動作：今回の構成では、astro build が記事と部品からHTML・CSSなどを生成します。生成
    物を配信するので、公開先でNode.jsを常時動かす必要はありません。

## CI/CD 

Github actionsを使用します。今回git側ではubuntuでビルドしています。
`.github/workflows.yml`を作成して完成です。
```yml
name : Build portfolio

on:
  push:
    branches: [ main ]
  workflow_dispatch:

permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v7
  
      - name: Set up Node
        uses: actions/setup-node@v7
        with:
          node-version: "22"
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

```
